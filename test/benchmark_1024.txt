Notes:
- Large matrix: overhead negligible, realistic performance
- OpenMP achieves exceptional scaling: 3.97x on 8 cores
- Memory bandwidth saturation point visible
- GPU transfer overhead remains constant (negligible on large ops)
- Hybrid shows diminishing returns vs pure OpenMP

Performance Analysis:
- OpenMP Efficiency: 99.3% ≈ OPTIMAL scaling
- Hybrid Efficiency: 75% ≈ Reasonable but suboptimal
- Memory-bound computation clearly visible
- Main memory throughput: ~40-50 GB/s
- GEMM memory intensity: insufficient to saturate all cores

Bottleneck Analysis:
- Primary: Memory bandwidth (DDR4 51 GB/s theoretical)
- Secondary: Cache contention (8 cores sharing 20 MB L3)
- Tertiary: Cache misses due to working set size

GFLOPs Analysis:
- Serial: 1.65 GFLOPs (heavy cache misses)
- OpenMP: 6.55 GFLOPs (4x improvement despite memory limit)
- Theoretical peak (CPU): 150+ GFLOPs
- Practical peak (memory-bound): ~8-10 GFLOPs
- OpenMP achieves 65% of practical peak

Recommendations:
1. For even larger matrices (N > 2048), use tiled/blocked GEMM
2. Cache-optimal implementation crucial beyond N=2048
3. GPU accelerator helpful for dedicated graphics cards
4. Load balance tuning important for hybrid approach
